# 课程签到管理系统 + Agent 对话式工作台

一个基于 **uni-app x + UTS + Vue 3** 的课程签到管理项目。在原有管理员 / 教师 / 学生 SaaS 界面之上，新增 **管理员 Agent** 与 **教师 Agent**：用户可以通过自然语言完成查询、新增、修改、删除，并由通用槽位填充状态机负责追问与二次确认。

## 技术栈

- **uni-app x**：一套代码运行到 Web / App / 微信小程序（以 HBuilderX 实际支持为准）
- **UTS**：强类型脚本，核心逻辑位于 `utils/agentEngine.uts`
- **Vue 3**：`.uvue` 单文件组件，Options API
- **rpx + Flex**：页面统一使用 rpx 与 flex 布局
- **纯前端数据**：`utils/userData.uts`、`courseData.uts`、`checkinData.uts` 内存表

## Agent 核心架构

### 1. 通用槽位填充状态机

引擎状态：

```text
idle
  ↓ 识别到写操作意图
awaiting_slots（缺少参数，继续追问）
  ↓ 参数补全
awaiting_confirm（展示确认卡片）
  ↓ 点击“确认执行” / 回复“确认”
idle（执行真实数据操作）
```

所有待执行操作统一存放在 `PendingOperation` 中，包含：

- 操作意图：`add_user` / `add_course` / `update_user` / `update_course` / `delete_user` / `delete_course` / `delete_checkin`
- 用户槽位：姓名、学号、角色、目标用户
- 课程槽位：课程名、老师、时间、目标课程
- 删除槽位：目标 ID 列表
- 修改槽位：字段名、新值

示例：

```text
用户：新增用户张三
Agent：收到，正在为您新增用户【张三】。请问学号和角色是什么？
用户：学号202401，角色学生
Agent：即将新增用户：张三(202401) / 学生，请确认。
       [确认执行] [取消]
```

### 2. 统一确认与回传指令

所有写操作必须二次确认，确认卡片统一使用：

```ts
actions: [
  { text: '确认执行', actionType: 'confirm_execute' },
  { text: '取消', actionType: 'cancel_action' }
]
```

前端点击按钮后回传：

```text
/confirm_execute
/cancel_action
```

引擎执行真实数据操作并返回结果；删除、修改、新增均不可跳过确认直接执行。

## 业务能力与权限边界

| 能力 | 管理员 | 教师 |
|---|---|---|
| 查询用户 | 全部用户 | 自己课程下产生过签到的学生 |
| 查询课程 | 全部课程 | 仅自己名下课程 |
| 查询签到 | 全部签到 | 仅自己课程的签到 |
| 新增用户 | ✅ | ❌ 权限不足 |
| 新增课程 | ✅ 可指定任意教师 | ✅ 只能给自己新增 |
| 新增签到 | ❌ 禁止 | ❌ 禁止 |
| 修改用户 | ✅ 学号 / 角色 | ❌ 权限不足 |
| 修改课程 | ✅ 时间 / 老师 | ✅ 仅自己课程 |
| 删除用户 | ✅ | ❌ 权限不足 |
| 删除课程 | ✅ 全部 | ✅ 仅自己课程 |
| 删除签到 | ✅ 全部 | ✅ 仅自己课程 |

### 查询

- 触发：`查看所有签到`、`查看课程列表`、`查询所有用户`、`查询我的学生`
- 返回卡片列表，UI 严格限制最多显示 10 行，超过时提示“仅展示前 10 条，点击下方按钮查看全部”。
- 卡片附带跳转按钮：
  - 签到：`前往签到管理`
  - 课程：`前往课程管理`
  - 用户（管理员）：`前往用户管理`
- 教师跳转 URL 自动携带 `teacherName`，保证目标页仍按当前教师过滤。

### 新增

- **新增用户**：仅管理员，槽位为姓名、学号、角色。
- **新增课程**：管理员可指定任意教师；教师自动归属自己。槽位为课程名、开课时间、授课老师。
- **新增签到**：禁止。签到记录必须由学生端真实提交产生。

### 修改

- **修改用户**：仅管理员，支持修改学号、角色。
- **修改课程**：管理员可改所有；教师仅可改自己的课程，支持修改上课时间、授课老师。
- 时间支持 `15:30` / `15点30分`；只给 `15点` 时会追问分钟。

### 删除

- 用户：仅管理员，管理员账号受保护。
- 课程：管理员全部；教师仅自己课程。系统预置课程受保护。
- 签到：管理员全部；教师仅自己课程的签到。
- 所有删除进入 `awaiting_confirm`，展示确认卡片，绝不可直接删除。
- 拒绝“删除所有 / 清空 / 批量删除”。

## 安全与防御

- 输入长度限制、零宽字符清理、全角转半角、空白归一化。
- 敏感词黑名单：拦截“忽略指令”“系统指令”“prompt”“写代码”“你是谁”等。
- 注入正则 + 去标点二次扫描：识别 `忽 略 指 令`、`忽.略.指.令`、`忽/略/指/令` 等拆字绕过。
- 未命中业务意图时统一回复：
  > 我是签到业务助理，仅支持处理用户、课程和签到数据的查询与操作哦。
- 权限在引擎内部校验，教师越权会返回“权限不足”。
- 所有内容通过 `{{ }}` 文本渲染，不使用 HTML 注入。

## UI / UX

- 管理员与教师 Agent 均使用浅色简约风：
  - 页面背景：`#f5f6fa`
  - 用户气泡：`#007aff` 蓝底白字
  - Agent 气泡：`#ffffff` 白底 `#333`
  - 输入框：白底 + 灰色边框 + 圆角
  - 卡片：白底 + `20rpx` 圆角 + 明显阴影
- 快捷指令（Chips）：
  - 管理员：`查询所有用户`、`新增用户`、`删除课程`、`所有签到`
  - 教师：`查询我的学生`、`新增课程`、`修改开课时间`
- 新消息自动滚底；卡片动作按钮统一使用浅蓝底。

## 本地运行

1. 安装 **HBuilderX**（建议使用支持 uni-app x 的较新版本）。
2. 使用 HBuilderX 打开项目根目录（包含 `manifest.json` 与 `pages.json` 的目录）。
3. 运行：
   - **Web**：运行 → 运行到浏览器 → Chrome
   - **App**：运行 → 运行到手机或模拟器 → Android / iOS
   - **微信小程序**：运行 → 运行到小程序模拟器 → 微信开发者工具
4. 使用教职工登录：
   - 管理员：`13900000001`
   - 教师：`13800000001`（赵老师）
5. 进入管理台 / 教师台，点击顶部 **✨ AI 助手**。

> 项目没有 `package.json`，不依赖 npm 安装；数据保存在内存中，刷新或重启后恢复初始数据。

## 说明

- Agent 为**纯前端规则引擎**，不调用任何大模型或外部接口。
- 新增 / 修改 / 删除直接作用于 `utils/` 中的内存数据表，便于演示。
- 新增课程默认签到窗口为开课时间前 10 分钟到后 20 分钟，坐标默认 `0,0`。
- 页面跳转与卡片动作均使用跨端 API，未使用平台特定能力。
